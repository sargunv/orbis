# Style support

Generated by `cargo xtask support` from style-spec 26.5.1's `v8.json`,
orb-style's property table and the latest fixture results in
`docs/scratch/rt` (`native`, `query/native`). Don't edit it by hand: run the fixtures, then the
task.

## Previews

Style inputs beyond the approved spec are previews, off unless a map
names them: `MapOptions::previews` in orb-api, `previews: [...]` (or
`"all"`) in the web package, `--previews` on the CLI. With a preview
off, its inputs warn and fall back to their defaults. A preview may
change or disappear at any time.

| Preview | What it enables |
|---|---|
| `style-spec#1623` | `equirectangular` and `natural-earth` projection types, handing over to Mercator between zooms 6 and 7. The proposal's name is still open (`equirectangular`, `eqc`, `geodetic`); Orbis keeps `equirectangular`. No proposal covers `natural-earth` yet. |
| `style-spec#1865` | The `equal-earth` projection type, and zoom interpolations from it to `mercator`, handing over to Mercator between zooms 6 and 7 by default. |
| `style-spec#1866` | `projection.transition`: the `[start, end]` zooms a low-zoom projection hands over to Mercator between, or `false` for none. The interpolation syntax stays supported. |
| `orbis:crs` | Coordinate reference systems as the projection type (`EPSG:3413`, or a parametric kind such as `polar-stereographic` with PROJ-named numeric parameters beside the `type`) and OGC 2D tile matrix sets on sources (`tileMatrixSet`: a registered identifier or an inline document). Our own design; no proposal yet. |
| `orbis:expressions` | Each property reads every input Orbis honours in the phase it is evaluated in, whatever the spec's `property-type` says; the support matrix lists them. Among them are the camera's `["pitch"]` and `["bearing"]` (degrees) in paint drawn every frame, for values the same for every feature. Our own design; no proposal yet. |

## Phases

Orbis has no paint and layout: each property is evaluated in one
phase, which bounds the inputs it can follow.

| Phase | Evaluated | A change shows | What runs again | Cost | Can follow |
|---|---|---|---|---|---|
| tile | Once per tile at the tile's zoom, on the job workers | When the tile is laid out again: an edit, or crossing a whole zoom | The layer's layout in every tile it draws | Highest: job time and uploads per tile | zoom, data |
| placement | Per camera snapshot, in placement | At the next placement | Collision and placement of the layer's labels | Placement time; no layout | zoom, camera, data |
| frame | Every frame in the shaders, per feature: property rows at the tile's zoom and the next, or the feature-state table | The next frame | Row or state-table uploads for data; node paint for the rest | Low: a uniform, or rows written once per tile | zoom, camera, data, state |
| layer | Every frame, once for the whole layer | The next frame | The node's paint | Lowest | zoom, camera |

## Properties

Inputs are `zoom`; `camera`, the camera's pitch and bearing; `data`, the
feature's properties, id and geometry; and `state`, its feature state.
**Spec** lists the spec's expression parameters; **GL JS** and **Native**
the first versions with the property and its data-driven form (the
spec's `sdk-support`; Native is Android's); **Orbis** what Orbis reads,
the spec's inputs and, after `+`, those `orbis:expressions` adds;
**Fixtures** the render tests named for the property that pass, per
fixture run.
