Technical plan · codename Orbis

One Rust core, on the web and native, GPU-driven, on any surface

Orbis is a proposed new, third map engine, alongside MapLibre Native and GL JS. One small Rust core runs in browsers (plain wasm + WebGPU) and natively on Windows, macOS, Linux, Android and iOS from its first release. The GPU owns per-frame work, and the world is a plane, sphere or WGS84 ellipsoid fed from any OGC TileMatrixSet. It replaces neither engine, reads the same inputs, learns from both and owes neither API compatibility.

Codename. Orbis is a working codename; where the project lives is an open question. Identifiers use placeholders: orb- (crates), orb_ (C ABI), orbis (web package, unpublished).

A third engine, beside the two that exist

Native and GL JS are unchanged by this plan. The three share inputs and contracts; Orbis borrows only liberally licensed pieces.

Out of reach for both engines today

Some things are structurally out of reach for both existing engines without rewriting their foundations:

  • One engine on native and web without Emscripten, COOP/COEP or JSPI. Native-on-wasm is 2.21 MB br and needs all three gap-web-single-core-feasibility §0, §1.3 verified.
  • A GPU-driven frame. GL JS issues 449.6 state-changing draws per frame for Liberty at Tokyo z15 gl-js#8474; Native's drawables rewrite measured 0.86× legacy CPU throughput native#2787; 996 renderables were drawn for 4 visible labels native#3223 verified.
  • A geodetic world. Both engines wrap Mercator tile space onto a unit sphere crs-projection §0 verified; ECEF/ellipsoid scenes and any OGC TileMatrixSet need a different world model.
  • Guest embedding on a host's GPU device and depth buffer, and an accessibility tree built from placement.

§0 · summary

What it is, what it is not, and what ships first

An embeddable interactive engine whose first release (M5) runs from one core on every target. Any CRS, globe and ellipsoid, 3D and guest embedding are designed in from day one and shipped as later milestones.

Also out: a JS VM in styles (Tangram-ES embedded Duktape and JavaScriptCore gap-prior-art §2.2 verified); SharedArrayBuffer, JSPI or Memory64 on the default web path; SQLite offline databases; Mapbox-only spec features; WebGL1 and GLES 2.

§2

Eleven design principles

Most are enforced by CI rather than by review.

  1. 1
    One implementation per concern, one owning crate.

    CI keeps a concern → crate registry.

  2. 2
    The core never blocks, spawns threads or touches the OS

    below orb-runtime; kernels build for wasm32-unknown-unknown and wasm32-wasip2 in CI.

  3. 3
    Every milestone runs on the web and natively,

    from the same crates, under CI.

  4. 4
    The GPU does per-frame work; the CPU does per-change work.

    "Objects touched on [S] per frame" and "commands recorded per camera-only frame" are CI counters from the first renderer commit.

  5. 5
    Design for the modern API; degrade explicitly.

    Compat implements a declared subset from Modern's data and may not add requirements upstream. Gaps are warnings, never blank screens.

  6. 6
    Plain data crosses every boundary;

    closures never do gl-js#8533 verified.

  7. 7
    No coordinate system in public types or ABIs.

    A lint bans "mercator" in public items. Mercator leaks into stable ABIs today: mln_projected_meters_*, plugin tile_matrix crs-projection §11.9 verified.

  8. 8
    Host services are traits with conformance suites,

    never link-time file selection (a Qt bidi stub reached an iOS build, ffi#788) verified.

  9. 9
    No silent fallbacks.

    Structured warnings tied to capabilities.json; strict makes them errors (Native renders globe styles flat silently, parser.cpp:100-112) verified.

  10. 10
    Correctness by construction.

    SoA, arenas, generational indices, fuzzing; no runtime canaries (native#4749: canaries cost 37% of app CPU) verified.

  11. 11
    Spec-heavy subsystems before GPU breadth.

    Style, expressions, text and placement land before 3D and embedding modes.

§3

Scope of the first release, and non-goals

The first release is broad on targets and v8 coverage, and deliberately narrow on world model: Web Mercator only, with the hooks for everything else built at M0.

After M12

Point clouds, splats, ProjIR, expression-function and wasm plugins, a SharedArrayBuffer build, XR and game-engine packages.

Never

First-party declarative UI SDKs, SQLite offline, routing/geocoding/editing, a JS VM. Wrappers such as maplibre-compose own UI.

§4

Platform baselines and GPU tiers

Every target platform has a modern GPU API on most current devices. Orbis designs for that Modern tier and serves the shrinking remainder with a separate, reduced Compat tier that runs on the same data and may not shape the main path.

Tier coverage

Sources: gpuweb wiki verified; Android Vulkan ≥1.1 on ~87% of devices verified (secondary). A device can drop from Modern to Compat at runtime (crash sentinel, allowlist); every choice and fallback is reported in map.diagnostics.

Four tiers

Why a reduced tier instead of a lowest common denominator inferred

The remainder (iOS < 26 browsers, Firefox Linux/Android, Android < 12 or flagged drivers, WebViews without WebGPU) is shrinking and identifiable. Shaping every algorithm for it would cost the main path storage buffers in the vertex stage, compute-fed indirect draws and a single submission model; serving it with a reduced tier costs one GL executor, CPU cull kernels and a texture-fetch shader variant.

Selection order

Floors inferred

  • Android API 24 (matches maplibre-compose's minSdk 24 verified), arm64 + x86_64, texture targets API 26 (AHardwareBuffer); iOS 16; macOS 13; Windows 10 21H2 x64/arm64; Linux glibc 2.31/musl.
  • Browsers for Modern: Chrome/Edge 113+ desktop, 121+ Android; Safari 26; Firefox 141 (Windows)/147 (macOS).
  • Compat: Chrome/Edge 110+, Firefox 128 ESR+, Safari 16.4+ (worker rendering 17.2+).

Boundary rules (CI-enforced)

  1. Below orb-runtime: no threads, no I/O, no GPU handles. Only orb-hal-* touches GPU APIs, only orb-host-* the OS or browser, only orb-capi/orb-web export symbols.

  2. Job crates are share-nothing and never depend on scene crates.

  3. No public item names a CRS.

  4. Compat may not constrain Modern: Compat consumes orb-scene data and layout output; nothing in the Modern path depends on Compat code or features; a layout change needed only by Compat is rejected.

  5. unsafe only in orb-hal-*, orb-capi, orb-web, orb-jobs and audited SIMD kernels; elsewhere #![forbid(unsafe_code)].

  6. cargo deny licence allowlist (MIT, Apache-2.0, BSD, Zlib, ISC, file-level MPL-2.0), crate-graph check, cargo-semver-checks on orb-api, public-item lint, per-module size gates.

Object model: four nouns, refined from ffi#706

Runtime

executor, host services, registries, shared caches (tiles by data TMS, glyph pages, pipelines); serves many maps.

Map

style and scene document, camera, sources, feature/global state, queries, accessibility snapshot; no GPU state. Queries run on its published snapshot; Native puts them on Renderer, forcing the FFI into warm-up renders sdks-local §0.7 verified.

Renderer

GPU tables, arenas, atlases, pipelines, current placement. It outlives targets (backgrounding, surface swaps; ffi#706, compose#1377) and rebuilds from cached TileFrames after device loss.

Target

surface, owned texture, imported host texture with optional host depth (M9), or multi-view (M9): CAMetalLayer, ANativeWindow, HWND, Wayland, <canvas>/OffscreenCanvas, MTLTexture, VkImage, ID3D12Resource, GL texture, GPUTexture, wgpu::Texture.

§7

Execution model: a core that owns no thread

A scene state machine plus pure jobs behind an Executor. Reads are synchronous snapshots and commands are asynchronous with generations, so the same API works on a core thread, an engine's game thread, a web worker or the caller's stack.

Roles × modes

thread: "main" is automatic when OffscreenCanvas transfer or WebGPU in workers is missing, and used by hosts that supply their own GPUDevice or WebGL2 context (Compose web runs GL JS in Skia's context today sdks-local §3.3) verified.

Invariants in every mode

ffi#760's model, "easiest of the four migrations" for a production Go tile renderer sdks-local §2.10 verified

  • Commands from any thread return completions with a generation.
  • Snapshot reads are synchronous, never touch mutable state, and can be fenced on a generation.
  • No synchronous GPU waits: readback, mapAsync, adapter/device requests and pipeline creation are async, so JSPI is never needed.
  • One versioned update per command group.
  • No host pumping ffi#352.

Where the web scene renders

Default: render worker + ui role on main, because GL JS's main thread is busy 2,089 ms during load against 609 ms in its worker, TinySDF alone 27.6% gl-js#8426, and app frameworks compete for main verified. Nothing in Orbis's API forces the scene onto main.

Gesture latency (+1 frame reviewer-reported)The ui role owns the camera, so DOM consumers see it immediately; only the canvas lags.
Overlay skewA transferred OffscreenCanvas cannot commit atomically with the DOM. Default overlays are engine-drawn view annotations (composited in-frame, collided with labels, depth-tested); DOM overlays are opt-in on frame acks, documented ±1 frame.
Terrain (M7)The ui role receives a compact elevation pyramid (min/max + 32×32 u16 coarse DEM per covered tile, ~2 KB each); sync unproject under terrain returns {lngLat, approximate: true}, unprojectExact is async.

§8

GPU: one HAL, a GPU-driven Modern path, a CPU-fed Compat path

Everything a frame needs lives in persistent GPU buffers. Per Modern frame: one cull/compact dispatch, one vertex-pulled drawIndirect per (render node, arena page), and a recorded bundle replayed unchanged. Compat runs the same data with CPU culling and direct draws.

The HAL

orb-hal is a small WebGPU-shaped trait (~2.5k lines): buffers, textures, samplers, bind groups, render and compute pipelines (lazy, async, with override constants), passes, bundles, indirect draws, timestamps, async readback, multi-view targets. Capabilities are detected at runtime into Caps {tier: M | C, fast_paths, limits}; no compile-time backends.

  • Web upload path: upload_from_js calls GPUQueue.writeBuffer on the underlying GPUBuffer via web-sys interop with wgpu (or bufferSubData on Compat), so payloads never pass through wasm memory. Proven in M0.
  • External resources (M9): import device, queue, colour and depth from raw Vulkan/Metal/D3D12 handles; semaphore/fence handoff.

orb-hal-wgpu

Covers: browser WebGPU; Vulkan, Metal, D3D12

Backends chosen at runtime, feature-gated per platform (iOS Metal only; Android Vulkan); on the web only wgpu's WebGPU backend, no naga, no GL. maplibre-rs's WebGPU-only build is 401 KB br with wgpu inside verified.

orb-hal-gl Compat

Covers: WebGL2, GLES 3.0+, GL 3.3

One hand-written glow executor over offline GLSL ES 3.00, GL state cache after GL JS (BSD-3); Compat only; lazy on the web.

Contingencies: a thin web-sys WebGPU HAL if wgpu's browser overhead breaks the M0 size gate; a thin Metal backend if wgpu's iOS size or performance misses M3.

Rejected: wgpu's GL backend (+1.7 MB raw / +610 KB gz in the browser verified; its least mature backend reviewer-reported); TS command-stream executors; Dawn ("tried Dawn, gave 5 MB extra size", native#317).

The GPU-driven frame

  1. 1
    Cull + compact, one dispatch. One thread per candidate (node, chunk): frustum, horizon and clip-rect test of bbox_tile through the tile row, fade, LOD; survivors append to the node's visible list (workgroup prefix sum; subgroup ballot where available) and write its indirect args. Symbol nodes compact by state word, so hidden symbols cost nothing downstream (native#4628 halved symbol time just by skipping hidden drawables) verified.
  2. 2
    Draw one drawIndirect per (node, arena page) with vertex pulling: vertexCount = 768, instanceCount = visibleChunks; the vertex shader maps instance → chunk → index → vertex and emits degenerate triangles past index_count. No multi-draw or indirect-first-instance needed. Points, circles, icons and glyphs are instanced quads.
  3. 3
    Replay. The pass's ~60–90 commands are identical across camera-only frames, so they are recorded once as a render bundle; tile arrival changes buffers, not commands.

Draws per frame, Liberty, Tokyo z15

GL JS baseline gl-js#8474 verified; Orbis values are targets, hatched inferred.

Three paths over the same chunk records

  • Modern: 1 dispatch + 1 bundle per frame and ~60–90 GPU draws.
  • M+: compute writes per-chunk DrawIndexedIndirect args for one multi_draw_indexed_indirect_count per (node, page), with no padding and fixed-function index fetch.
  • Compat: CPU SIMD cull over the same chunk records (~0.1 ms per 2k chunks, ≤0.3 ms budget), then multiDrawElementsWEBGL (~60–90 draws) or per-(node, tile) drawElements; tables read with texelFetch; hidden symbols early-out in the vertex shader (that cut Native's SDF pass from 60% to 13% of frame, native#3576) verified.

Costs, measured from M0 on Adreno, Mali, PowerVR and Apple GPUs: up to ~15% padded invocations, and lost post-transform reuse (fill vertices are reused ~1.5–2×, so vertex work can roughly double). A per-family cost model chooses among vertex pulling, on-change index compaction and M+ multi-draw. M1 also tries segment-instanced line extrusion.

Specialization

  • Each data-driven property's binding mode is an override constant; translators drop dead branches.
  • Only the bytecode class compiles the GPU interpreter (≤32 ops, ≤16 stops), after Native's GPUExpression native#2202 verified; a new expression in an existing class is a buffer write.
  • A typical basemap needs 25–40 pipelines, CI-counted; circle alone has up to 2^7 variants in Native verified. M1 measures interpreter register pressure on Mali-G52/G57, PowerVR and Adreno 6xx.
  • Today each UBO layout is written at least five times (49 C++ structs; GlobalPaintParamsUBO in 8 WGSL headers) native-render §0 verified.

First frame and projections

  • First frame: the cull pipeline first, then layers in order of first-visible coverage; a layer without its pipeline is not drawn and fades in later; warm starts use browser blob caches and native pipeline caches. The load gate is set from M3 measurements.
  • Projection modules expose project_tile, project_tile_3d, local_scale, extrusion_normal, horizon_clip; layer shaders never branch on projection (24 of GL JS's 71 GLSL files contain #ifdef GLOBE) gap-reconcile-claims §3 verified.
  • Seeds: Native's WGSL (4,567 lines, BSD-2); GL JS globe math incl. the Weierstrass form that fixed Mali precision gl-js#7916; single-pass halo gl-js#7436.

The Compat tier

Shares

Everything above orb-render: style, expressions, TileFrame, layout, chunk records, text, placement, camera, planner, queries. Arenas bind as vertex/index buffers; tile rows, properties, feature and symbol state are mirrored into RGBA32F/RGBA32UI textures; layer shaders are the same WGSL composed with the attribute/texture fetch.

Gives up

Declared in capabilities.json, each a warning, never a blank screen: GPU culling, compaction and indirect draws (no Modern performance budgets); GPU line-label placement (CPU, budgeted); terrain, atmosphere and lighting beyond v8 flat extrusion shading; ellipsoid/ECEF scenes, glTF, 3D Tiles, shadows, OIT, world-3d labels; data layers above ~250k features; SharedDevice and multi-view.

Keeps

v8 globe (sphere) and planar any-CRS, because Affine, CpuResample, RasterWarp and GpuPerVertex are vertex-shader work. Heatmap needs EXT_color_buffer_float.

Rules: LOC ceilings (~4k in orb-render, 5k in orb-hal-gl); a declared fixture subset by directory; new Modern features need no Compat version unless they are in the v8 2D subset; Compat never changes Modern data layouts.

Why keep it: without it, iOS < 26 browsers, Firefox on Linux and Android, Android devices outside the allowlist and WebViews without WebGPU would get no map. Its cost is mostly testing, which the shared fixtures and runners absorb.

Fallback, device loss, quirks

  1. Android allowlist: Vulkan is Modern only on Android 12+ with known-good GPUs and drivers, seeded from Chrome's WebGPU Android rollout (Qualcomm, ARM, Intel on 12+; Imagination on 16+; Xclipse pending) and Native's incidents; it grows only from farm and field telemetry.

  2. Quirks table (ANGLE FeaturesGL style), seeded from Goldfish, Adreno DEVICE_LOST native#4442, MediaTek and Huawei compiler crashes native#4464 native#4215, Exynos encode native#4184, PowerVR banding native#4506, Mali precision gl-js#7916, SwiftShader UBO order (FFI patch 0011), CGL bufferSubData stalls gl-js#8468, ANGLE-Metal flat varyings gl-js#8364 verified.

  3. Crash sentinel: a marker written before first pipeline creation and cleared after; if found at next launch, the device drops to Compat. #4464 and #4215 crash inside driver compilers, so offline compilation cannot avoid them verified. Pipelines are created on a watchdog thread.

  4. Device loss: streams are freed after upload; the Renderer rebuilds by re-running layout from cached TileFrames (or refetching from the HTTP cache), visible tiles first. On the web it may switch WebGPU → WebGL2 (Figma's design gap-prior-art §5.1 verified) and emits a capability-change event. Targets: ≤1 s to a correct visible frame on a mid-range phone; ≤2 s for a WebGPU → WebGL2 switch including the lazy Compat module.

§9

Scene and CRS: the world is a surface, not a square

A scene is a Surface, optional terrain, an ordered layer list, lights, an atmosphere, and a camera or external views. Each source keeps its own OGC TileMatrixSet; a per-source planner decides how data reaches the surface.

One scene, many appearances

Surfaces and projections as data

  • Aviation, drones native#3161, glTF georeferencing, 3D Tiles and XR assume WGS84; Native's globe proposal left the ellipsoid out native#4525 verified.
  • Surface operations (intersect_ray, tangent_frame, geodesic_interpolate, horizon) are written once, so the ellipsoid is cheap; v8 globe compiles to Sphere to match GL JS goldens.
  • A Projection is plain data plus f64 forward/inverse, affinity(tms) (affine or a curvature class), world_bounds (wrap periods, singularities), tile_volume, jacobian_hessian for the precision series, and a WGSL module implementing project_tile().

    Projections, precision, zoom

    Adaptivestyle-spec#1866 shape {type, lowZoom, transition: [z0, z1]}: v8 "globe" is web-mercator with a vertical-perspective low zoom over [11, 12] on a Sphere, following GL JS (the docs say 10 → 12; maplibre-rs#339) verified. Blends across incompatible surfaces are errors (today any array projection silently becomes a globe) verified.
    PrecisionAffine rows store the f64 camera-relative affine as f32 (deck.gl's approach, exact at any zoom); non-affine rows carry f64-derived C − camera, J, H, and the shader evaluates (C − camera) + J·d + ½dᵀHd. GL JS hands the globe to Mercator at z11–12 because f32 on a unit sphere gives "one value per 2.5 m" gljs-render §3.2 verified; Orbis keeps that handover for v8 globes until z18–z22 agreement passes on the farm.
    Camera and zoomCameraState {target: Geodetic, resolution_m_per_px, bearing, pitch, roll, fov, altitude?, padding} as single-writer snapshots, pitch/roll unclamped (Native Android hard-codes three 60° clamps, native#4530) verified.     §10

    Data formats: columns in, GPU tables out

    TileFrame is the single in-memory vector representation, after MLT's FeatureTable sdks-ecosystem §4.1 verified, built on mlt-core. Filters and paint become column scans, property columns go to the GPU as tables, and on the web every copy is counted.

    Where the wins are

    • Raw decode is roughly a wash: MLT median-tile decode with gzip is 113–117% of MVT; earcut ~2% of GL JS worker time gl-js#8425 verified.
    • The wins: no per-feature allocation, filters and paint as column scans (a ["==", ["get","class"], "primary"] filter becomes a dictionary-code compare), columns uploaded directly as GPU tables, and selective decode for queries.
    • Pre-tessellation is opt-in per source (+22–36% size, +27–145% decode) verified.
    • Render streams use tile-local integer positions, 32-bit indices (no 65k segmenting), feature_slot ranges and a per-tile hit index (8–16 B per feature); they are freed after upload.

    Feature and global state

    Per source, id → state_index (promoteId values, interned strings, the MLT id column for generateId); a global table with a per-style compiled row layout (≤32 booleans, ≤4 f32, string enums; typically 24 B); a per-tile slot → state remap only for sources whose style reads feature-state; arbitrary JSON state falls back to CPU re-evaluation of the affected ranges.

    Feature state also drives icon opacity, size scale and in-atlas icon-image swaps gl-js#5542; promoteId/generateId work everywhere (native#4737 open) verified.

    Data layers (M11)

    A columnar source family: Arrow/GeoArrow batches (zero-copy natively with a release callback; on the web transferred to a disposable ingest worker and copied once per shard), packed geometry aligned to MLT streams ffi#584; jobs build a Hilbert sort, a packed R-tree over chunk bounds, ≤256-element chunks, LOD bands and property columns; the GPU culls them with the tile cull compute and draws instances. Data-layer symbols join basemap collision; feature state, queries and the accessibility snapshot are shared. Modern-only: GPU aggregation (heatmap density, hexbin, grid) and opt-in symbol-placement-mode: "gpu-approximate". Targets inferred low confidence: 10M points at 60 fps on an M-series laptop, 2M on a mid phone; ~250k on Compat.

    Data across web boundaries

    A SharedArrayBuffer build (opt-in, after M12) would remove the job → render copy and allow in-job cancellation; no target depends on it. Offline is PMTiles extracts + an HTTP cache with batched metadata writes; Native's per-hit fsync cost 1,011 of 1,327 ms on cold open native#4748 verified.

    §11

    Style handling: v8 in, unmodified; new capabilities in a scene document

    orb-v8 compiles v8 losslessly into a typed Style IR, the engine contract. Orbis never adds keys to v8 JSON; anything v8 cannot express lives in a separately versioned scene document that references an unmodified v8 style, so a v8 document means the same thing in every engine.

    Why v8 cannot be the executed model: it bakes in Mercator (scheme, {bbox-epsg-3857}), lacks TMS, surface, composition, lighting, 3D and a11y, and carries legacy coercions the engines disagree on.

    Frozen semantics. Each release pins a spec version, a fixture snapshot (GL JS render and query tests, Native's unique tests, the spec's expression fixtures) and a GL JS version.

    2. spec text

    IR and pipeline

    IR: internal, versioned, CBOR-cacheable, buildable from Rust without JSON.

      Expressions compile once and ship to workers as bytecode; GL JS parses each at validation, on main and in every worker, and Native clears every source on a new style and has no validator style-spec §2.5, §6 verified. map.edit(tx => …) publishes one snapshot, giving wrapper reconcilers a diff target (removing the flutter-maplibre-gl#477 class) verified.

      Expressions: one IR, three backends

      The 88 v8 operators with ParsingContext semantics, ported from the TS reference into an SSA DAG with a dependency bitset (zoom, pitch, feature, feature_state, global_state, elevation, line_progress, heatmap_density, resolution, image).

      1 · register VMno per-feature allocation
      2 · SIMD column evaluatordictionary inputs once per entry
      3 · GPU bytecode interpreterbytecode-class pipelines only

      A constant ↔ data-driven flip is a block write plus at most a column job and an async pipeline, never a relayout (GL JS reloads the source and Native relayouts today, style.ts:1414-1425) verified. Every fixture runs on every backend that can evaluate it. Locale operators use the host Locale service with one conformance suite (number-format has 5 backends today and the FFI's browser build falls back to std::to_string, ffi#797) verified. No JS VM; expression-function plugins later through a reserved extern-op slot.

      The scene document

      It references or embeds an unchanged v8 style; it may decorate sources (TMS) and layers (a11y), add layers and sources using its modules, and set scene properties; it may not change v8 meanings. Every module has an API equivalent (tx.setSurface(...)). Hover or focus an annotation.

      CRS/TMS and composition are the candidates for spec RFCs with fixtures. An offline orb-v8 import --dialect mapbox-v8 tool converts same-key, different-schema features (projection, sky) into a v8 style plus a scene document gap-prior-art §6.15.

      §15

      Extensibility: one model, per-runtime registries, built-ins as plugins
